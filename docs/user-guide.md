# Mutiara Line Community Desk 使用手册

本手册适用于本地运行的 Penang LRT Mutiara Line 社区信息平台。网站是课程项目的工作模拟，公告由平台用户发布，不等同于政府或交通运营商的官方通知。

## 1. 开始使用

### 1.1 打开网站

启动网站后，在运行网站的电脑上打开 `http://localhost:5173/`。首页介绍项目，并提供居民、主管部门协作人员、施工团队三个入口。居民网站的直接地址是 `http://localhost:5173/community`。

同一局域网的手机或其他电脑可以打开 `http://网站电脑的 IPv4 地址:5173/`。网站电脑必须保持开机且服务持续运行。跨电脑共享的是 MySQL 数据，而不是浏览器里的 `localhost` 地址；每台组员电脑可以各自运行网站，并连接同一个 MySQL。地图底图和地点搜索需要互联网。

| 身份               | 注册                  | 登录               | 工作页面     |
| ------------------ | --------------------- | ------------------ | ------------ |
| 居民、通行者、商户 | `/login`              | `/login`           | `/community` |
| 主管部门协作人员   | `/authority/register` | `/authority/login` | `/authority` |
| 施工团队           | `/team/register`      | `/team/login`      | `/team`      |

页面右上角可切换 English、中文、Bahasa Melayu。公告发布时只需填写一种语言；切换界面语言不会自动翻译用户写的公告或回执。

### 1.2 新电脑首次安装

1. 安装 Git、Node.js 22.12.0 或更新版本，以及 npm。
2. 克隆仓库并在仓库根目录运行 `npm ci`。
3. 复制 `.env.example` 为 `.env.local`，填写 `DB_HOST`、`DB_PORT`、`DB_NAME`、`DB_USER`、`DB_PASSWORD`。团队注册功能还需要 `TEAM_CODE_SECRET`；所有网站实例应填写同一个值。已有安装可暂时用 `LOCAL_SETUP_KEY` 作为兼容密钥。主管部门注册另需管理员生成独立随机值填写 `AUTHORITY_REGISTRATION_KEY`（至少 12 位），只私下交给获授权人员；未配置时关闭主管部门注册。不要把 `.env.local` 提交到 Git。
4. 按 [共享 MySQL 配置](shared-mysql.md)准备数据库、Tailscale 和数据库账户，运行 `npm run db:check` 检查连接。
5. 运行 `npm run build`，再运行 `npm start`。看到服务已启动后打开上面的地址。修改代码时可改用 `npm run dev`。

具体 PowerShell 命令、手机访问方法和更新步骤见 [README](../README.md)。MySQL 由数据库主机运行；DBeaver 是可选的数据库管理工具，平时可以关闭。

## 2. 居民、通行者与商户

### 2.1 浏览公告和地图

打开 `/community` 后，即使没有登录，也可以浏览已发布公告的概览、使用搜索框和类别筛选。五类主要信息是施工计划、道路封闭、商铺进出情况、公共交通和安全问题。点击“查看详情”时按页面提示登录居民账号；详情页面会展示完整说明、日期、地点、图片和相关地图链接。道路或地点的标注来自发布人员录入的数据，请结合现场标志核实。

### 2.2 注册和登录

进入 `/login`，选择创建居民账号，填写姓名、邮箱和至少 8 位密码。已有账号直接登录。居民账号只能进入居民功能，不能登录施工团队或主管部门工作台。

### 2.3 提交问题报告

在 `/community#report` 选择问题类别，填写具体地点、至少 15 个字符的描述和联系邮箱；可以附一张 JPG、PNG、WebP 或 GIF 照片，文件小于 5 MB。提交后页面会给出**报告编号**和**查询码**。请立即复制并妥善保存，尤其是查询码；不要公开给无关人员。紧急危险应直接联系当地紧急服务，不能只依靠网站报告。

### 2.4 查询处理进度

在 `/community#track` 输入报告编号和查询码，点击查询。使用原提交账号时，也可以按页面提示查看自己的报告。页面按“已收到 → 审核中 → 已分派 → 已解决 → 已关闭”显示进度，并列出每一次回执、时间和处理人员。如果处理人员在解决或关闭时关联了已发布公告，回执会有打开公告详情的链接。网站目前没有自动邮件或短信通知；需要回到页面查询。

### 2.5 保存关注类别

登录后到 `/community#alerts` 勾选关注的公告类别并保存。页面会列出与所选类别匹配的已发布公告。此功能是在网站内查看匹配信息，不会向邮箱或手机主动推送。

## 3. 主管部门协作人员

### 3.1 注册与登录

打开 `/authority/register`，选择“交通局”或“政府／地方主管部门”，填写姓名、邮箱、至少 12 位密码和管理员私下提供的主管部门注册密钥。注册成功后进入 `/authority`；已有账号从 `/authority/login` 登录。这是平台内的协作角色，不会验证真实政府人员身份。旧的固定演示代码不再有效。

### 3.2 查看和处理居民反馈

在工作台的“问题报告”标签选择一条报告，阅读描述及附图。选择新的处理阶段，填写至少 5 个字符的英文回执说明；中文和马来文说明可以补充。点击保存后，该次回执会保留在历史中，居民可看到。相同阶段可以继续补充回执，阶段不能倒退。选择“已解决”或“已关闭”时，可以关联一个**已发布**公告，居民会在对应回执中看到链接。反馈列表和历史记录较多时使用“加载更多”。

### 3.3 发布公告和图片

在“公告管理”创建公告，选择类别，填写标题、详情、地点及该类别需要的时间或地图信息。标题和详情只需一种语言。可以先保存为“草稿”，确认内容后改为“已发布”；“已归档”的公告不再向公众展示。每条公告可上传最多 4 张 JPG、PNG 或 WebP 图片，每张不超过 5 MB。保存失败时先查看页面提示，避免重复创建公告。

### 3.4 向施工团队提供注册码

在“施工团队注册码”标签查看当天的六位数字，只私下交给需要注册的团队成员。该码以马来西亚日期计算，每天零点更新。团队成员要在当天使用；过期后请重新查看。不同电脑的网站服务必须配置相同的 `TEAM_CODE_SECRET`，否则它们生成的代码可能不同。注册码用于**创建团队账号**，已有团队账号登录仍使用自己的邮箱和密码。

## 4. 施工团队

### 4.1 注册与登录

向主管部门协作人员取得当天注册码，打开 `/team/register`，填写姓名、邮箱、密码和六位代码。注册完成后进入 `/team`；已有账号从 `/team/login` 登录。注册码不等于 MySQL 密码，也不等于团队账号密码。

### 4.2 管理五类施工公告

在“公告管理”选择类别，填写地点和说明。可先保存草稿，再发布。发布前核对日期、现场标志和地图位置。

- **施工计划**：填写计划时间、预计完成时间及完成百分比。居民端显示进度条和按预计日期计算的剩余天数。
- **道路封闭**：搜索槟城的道路或地标，在地图上依次绘制受影响路段的起点、途经点和终点；多个分支可以新增多条路段。每条路段至少有两个点。
- **商铺进出情况**：命名并标记“原入口”和“临时入口”，再绘制受阻路段，写明顾客或送货人员的进出指引。
- **公共交通**：每组变更分别命名和标记原巴士站、新巴士站。可以新增第 2、3 组，最多 20 组。每组都需有两个站点。
- **安全问题**：填写安全说明，并通过地点搜索或地图点击选定问题位置。

路段、入口和站点发布后会显示在居民公告详情与完整地图中。站点变更只是平台公告，不会自动修改公交公司的实时路线或第三方地图。施工团队也可以在“问题报告”中查看反馈并记录处理回执；操作方式与上一节相同。

## 5. 一次完整的使用流程

1. 主管部门协作人员注册并登录，查看当天施工团队注册码，私下交给团队成员。
2. 团队成员注册并发布一条道路封闭公告，在地图上绘制所有受影响的路段。
3. 居民无需登录即可在 `/community` 看到公告概览；登录后查看详情和完整地图。
4. 居民发现现场标志与公告不符，提交报告并保存编号和查询码。
5. 施工团队或主管部门逐阶段记录调查和处理情况。处理完成后，将已发布的更正公告关联到“已解决”的回执。
6. 居民用编号和查询码查询，看到处理进度，并通过回执链接打开更正公告。

## 6. 数据、更新与常见问题

- **共用数据**：所有实例通过 `.env.local` 中的 `DB_*` 连接同一个 MySQL。账号、会话、公告、图片和报告都在数据库里。更换电脑不用复制浏览器数据；应备份整个数据库，包括 `uploaded_file` 表。旧 SQLite 数据不会自动导入。
- **更新代码**：在本机停止网站，运行 `git pull --ff-only`、`npm ci`、`npm run build`、`npm start`。本机有未提交改动时先处理改动，不要强制覆盖。
- **数据库连接失败**：先检查数据库主机是否开机、MySQL 服务是否运行、Tailscale 是否在线、3306 端口与数据库账号授权。使用 `npm run db:check` 做只读检查。DBeaver 能连接数据库不代表网站的 `.env.local` 已配置正确。
- **手机打不开网站**：确认手机与网站电脑在同一局域网，使用网站电脑的 IPv4 地址，检查 Windows 专用网络防火墙和 5173 端口。`localhost` 在手机上指手机自身。
- **地图或搜索不显示**：检查互联网连接；地图底图和地点搜索依赖外部服务。已保存的公告资料不会因为地图底图暂时不可用而删除。
- **注册码不正确**：确认使用当天的代码、网站服务的 `TEAM_CODE_SECRET` 一致，并在修改 `.env.local` 后重启网站。
- **密码忘记**：目前没有自助邮件重置功能。不要删除数据库来尝试恢复账号。
- **展示边界**：网站当前适合本地和可信网络内的课程演示。主管部门注册密钥只应私下发给获授权人员；本地 HTTP 不适合公开互联网环境。

开发者验证可运行 `npm run format:check`、`npm run lint`、`npm run typecheck`、`npm run build`。GitHub CI 另用隔离的 MySQL 测试数据库检查跨两个网站实例的数据流程；不会连接组员的共享数据库。
