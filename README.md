# Mutiara Line Community Desk（MySQL 共享数据库版）

这是 CMT322 Penang LRT Mutiara Line 社区平台。三位组员分别在本机运行 Next.js 后端，后端通过 Tailscale 连接同一个 MySQL 8.4 数据库。浏览器不直接连接 MySQL。

## 系统结构

- 项目入口 `/`：介绍平台并提供居民、主管部门协作人员和施工团队的分流入口；原居民网站移至 `/community`，仍可免登录浏览公开公告概览。
- 居民、通行者、商户：无需登录即可看施工公告概览；查看全文、提交问题和保存提醒时使用本地居民账号。
- 施工团队：使用独立的 `/team/login` 入口和本地团队账号；可以发布施工公告、查看居民报告和更新处理状态。
- 主管部门协作端：使用独立的 `/authority/login` 入口，由施工团队创建交通部门或地方主管部门协作账号；可查看反馈、逐阶段回执、关联已发布公告，并发布带图片的公告。这是项目的本地协作角色，不代表真实政府身份认证。
- 账号创建：居民可自行注册；首个施工团队账号需本地设置密钥；后续团队账号不可公开自行注册，主管部门协作账号由施工团队创建。入口页的工作账号“获取/设置”链接会明确说明此限制。
- 数据库：由 `.env.local` 的 `DB_*` 配置指定的共享 MySQL。
- 新上传图片：共享数据库的 `uploaded_file` 表，其他电脑无需复制文件即可查看。
- 登录会话：保存在共享 MySQL 中，通过 HttpOnly Cookie 识别，有效期 7 天。
- 界面语言：English、中文、Bahasa Melayu。

`.env.local` 和旧 `data/` 已被 Git 忽略。备份当前网站时应备份 MySQL 数据库，包含图片表；旧 SQLite 文件保留但不再使用。

完整配置步骤见 [三人共享数据库配置](docs/shared-mysql.md)。先完成该文档中的数据库准备，再启动网站。

## Windows 本地部署（新电脑）

安装 Git 和 Node.js 22.12.0 或更新版本。打开 PowerShell，检查版本并克隆仓库：

```powershell
git --version
node --version
npm --version
cd $env:USERPROFILE
git clone https://github.com/Dundun123123/322-Penang-Metro.git
cd .\322-Penang-Metro
npm ci
```

如果想放在其他位置，请在 `git clone` 前切换到目标文件夹；如果 GitHub 要求登录，请使用有权访问该仓库的账号完成认证。下列命令都应在仓库根目录执行。复制可公开上传的环境变量模板：

```powershell
Copy-Item .env.example .env.local
notepad .env.local
```

可以在 PowerShell 中生成随机密钥：

```powershell
$secretBytes = New-Object byte[] 32
$randomGenerator = [System.Security.Cryptography.RandomNumberGenerator]::Create()
$randomGenerator.GetBytes($secretBytes)
$randomGenerator.Dispose()
[System.BitConverter]::ToString($secretBytes).Replace('-', '')
```

把输出的字符串填在 `.env.local` 的 `LOCAL_SETUP_KEY=` 后面，保存。`.env.example` 只列出变量名，不包含可直接使用的密钥；`.env.local` 是每台电脑自己的秘密文件，不要上传。还必须填写 `DB_HOST`、`DB_PORT`、`DB_NAME`、`DB_USER`、`DB_PASSWORD`。先运行 `npm run db:check`。数据库服务器只需在一台电脑运行；不会自动建表或插入示例公告。

构建并启动正式本地服务：

```powershell
npm run build
npm start
```

电脑打开 `http://localhost:5173/`，施工团队入口是 `http://localhost:5173/team`。保持此 PowerShell 窗口运行；关闭窗口或让电脑休眠都会使网站暂时无法访问。停止服务时按 `Ctrl+C`。

主管部门协作入口是 `http://localhost:5173/authority/login`。同一局域网内也可将 `localhost` 换成主机的 IPv4 地址。

同一局域网的手机可以用这台电脑的 IPv4 地址访问。另开一个 PowerShell 窗口运行 `ipconfig`，找到当前 Wi-Fi 或以太网适配器的 IPv4 地址，然后在手机打开 `http://该地址:5173/`（例如 `http://192.168.31.174:5173/`）。也可以尝试 `http://电脑名称:5173/`，电脑名称用 `hostname` 查看；如果手机无法解析名称，请使用 IPv4 地址。电脑和手机必须处于同一可信局域网；Windows 防火墙询问时只允许“专用网络”，不要开放路由器的公网端口。地图底图和地点搜索仍需要互联网。

## 启动开发版本

仅在修改代码时使用；先停止占用 5173 端口的正式服务，再在项目根目录运行：

```powershell
npm run dev
```

开发模式同样使用 5173 端口，但正式展示建议使用上面的 `npm run build` 和 `npm start`。

## 创建账号

### 居民账号

打开 `/login`，选择“创建居民账号”，输入姓名、邮箱和至少 8 位密码。账号和密码哈希保存在共享 MySQL 中，任意组员的网站实例均可登录该账号。

### 第一个施工团队账号

打开 `/team/login`。系统没有团队账号时会显示首次设置表单，需要填写本机 `.env.local` 中的 `LOCAL_SETUP_KEY`。不要把该密钥写入文档或提交到 GitHub。首次创建团队账号后建议更换设置密钥并重启网站；系统已有团队账号后，网页不会再允许创建首个团队账号。

### 主管部门协作账号

施工团队登录 `/team`，打开“主管部门账号”，填写姓名、邮箱、部门和至少 12 位临时密码。创建后把登录地址 `/authority/login` 和密码通过私下渠道交给协作人员。主管部门账号不能自行注册，也不能通过施工团队入口登录；施工团队账号不能通过主管部门入口登录。此账号只是本地项目权限，不构成官方机构身份核验。密码目前没有邮件重置流程。

### 反馈回执和公告图片

施工团队和主管部门都可在“问题报告”中查看反馈及居民上传的照片，选择处理阶段（已收到、审核中、已分派、已解决、已关闭），每次填写处理说明后保存。相同阶段可多次回执，每条记录保留时间和回执人，阶段不能倒退。居民输入报告编号和查询码（或用提交报告的账号）即可看到进度及所有回执。问题解决或关闭时，可选一个**已发布**公告关联；居民回执中的链接会打开该公告详情。若公告后来撤下，链接不会继续显示为公开结果。没有自动邮件或短信通知。

工作台中的反馈列表及单条反馈的回执历史均按每页 30 条加载；需要查看更早内容时点击“加载更多”，避免一次读入全部数据。

两端都能在公告表单中选择最多 4 张 JPEG、PNG 或 WebP 图片（每张不超过 5 MB）。新公告如选“已发布”并带图片，系统会先保存草稿、上传图片，再发布；上传失败时保留同一草稿及已成功上传的图片，重试会继续上传而不会重复创建公告。新图片与公告数据都保存在共享 MySQL 中，备份数据库时应包含 `uploaded_file` 表。

## 施工团队的五类公告

施工团队登录 `/team` 后，在“公告管理”顶部选择要新建的部分。公告标题和详情只需用一种语言填写；可先保存为草稿，资料核实后再选择“已发布”。

- **施工计划**：填写预计完成时间，用滑块或数字框更新已完成百分比。系统按预计完成时间自动计算还需多少天，并在居民公告概览及详情中显示进度条。这个天数是日期估算，不是按进度百分比推算，也不是工期保证。
- **道路封闭**：搜索槟城道路或地标，沿受影响道路依次点击起点、转弯点和终点；遇到同时施工的分支，点击“新增路段”继续绘制。每条路段至少要有起点和终点才能发布。
- **商铺进出情况**：分别选择“原入口”和“临时入口”，通过搜索结果或点击地图设置两个不同颜色的地点，再切换“受阻路段”绘制影响进出的道路。填写顾客、送货人员的通行说明后发布。发布时必须有两处已命名的地图点和一条完整受阻路段。
- **公共交通**：每组“站点变更”都包含一个原巴士站和一个对应的新巴士站。分别填写名称，在地图工具中选择该组的原站或新站，再搜索或点击地图标记位置；用“新增一组站点”建立第 2、3 组，必要时可删除。居民会按编号看到所有对应关系和地图上的编号标记。发布时每组都必须有两个已命名的地图点；最多可记录 20 组。
- **安全问题**：填写危险情况与受影响地点，搜索地点并选择结果，或直接点击地图标记准确位置；可补充安全提醒或临时通行指引。发布时必须在地图上选定一个地点。安全公告不同于居民提交的问题报告；紧急危险仍应联系当地紧急服务。

地图点的颜色旁同时显示“原入口／临时入口”“原巴士站／新巴士站”或“安全问题地点”文字，不需要仅靠颜色辨认。已发布的路段和地点会显示在居民公告详情及“查看完整地图”页面。旧公告的单条路线会自动作为“路段 1”读取；现有公告、居民账号和报告不会因新增字段被删除。地图底图和地点搜索需要联网。站点变更是施工团队发布的信息，不会自动更改公交公司的实时线路或第三方地图。

## 更新已经部署的网站

先在运行网站的 PowerShell 窗口按 `Ctrl+C` 停止服务。在仓库根目录执行：

```powershell
git pull --ff-only
npm ci
npm run build
npm start
```

更新代码不会自动删除被 Git 忽略的 `.env.local` 和 `data/`，但更新前仍应备份数据。如果 `git pull --ff-only` 因本地代码改动而停止，不要强制覆盖；先处理本地改动。

## 搬迁和备份数据

GitHub 仓库只包含代码。使用 MySQL 备份工具或 DBeaver 备份整个 `penang_metro` 数据库（包括 `uploaded_file`）。换开发电脑只需拉取代码和设置自己的 `.env.local`，无需复制数据。迁移数据库服务器时需恢复完整备份并调整每人的 `DB_HOST`、数据库授权与防火墙。

旧 `data/mutiara-community.db` 和 `data/uploads/` 不会自动导入 MySQL，也不会被本次改动删除。需要保留的旧数据请先备份，再单独安排迁移；不要为了排错删除它们。

## 常见问题

- 手机打不开：确认电脑与手机在同一网络，检查 Windows 防火墙是否允许 Node.js 访问专用网络，并确认路由器没有开启设备隔离。
- 端口被占用：关闭原来的 Node.js 服务，再运行启动命令。
- 忘记居民或团队密码：当前版本没有邮件找回功能。请由维护人员安排账号恢复，不要删除数据库或旧文件。
- 迁移电脑：按上面的搬迁和备份步骤操作，每人使用各自的数据库凭证。
- 外网访问：此配置只用于本机和可信局域网。不要把 5173 端口直接暴露到互联网；若要公开上线，需要 HTTPS、反向代理、备份和更严格的安全配置。

## 主要命令

```powershell
npm run dev    # 开发模式，修改代码后自动刷新
npm run build  # 检查并构建正式版本
npm start      # 运行已构建的正式版本
npm run format # 使用 Prettier 统一格式
npm run format:check # 检查格式，不修改文件
npm run lint   # 代码检查
npm run typecheck # TypeScript 类型检查
```

## GitHub CI

`.github/workflows/ci.yml` 会在推送到 `main` 和针对 `main` 的 Pull Request 时运行：`npm ci`、Prettier 格式检查、lint、TypeScript 类型检查和正式构建。提交代码前运行 `npm run format`；CI 的 `format:check` 只检查，不自动改动代码。CI 不使用本机 `.env.local`、数据库或上传图片，也不会自动部署到本地电脑。部署更新仍按上面的“更新已经部署的网站”步骤手动执行。
